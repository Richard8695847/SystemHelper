已分析版本
  • 它不是 App，是预置组件。 要求 READ_PRIVILEGED_PHONE_STATE（仅 priv-app / 平台签名可得）与 sharedUserId，普通安装流程拿不到这些权限。所以它能跑，只可能是出厂就在系统分区里。
  • “用户许可”是个常量。 GlobalSetting.isUserPermissionOpen 默认 true，而且门关着仍然 insertRecord；另一条路径把系统的 device_provisioned（开机向导完成标志）当作“已同意”。不存在同意对话框。
  • 采的东西远超“注册”所需。 注册只要 5 个字段；实际采了 40+，其中至少 20 个与注册无关：应用清单+前台时长+分卡流量、连续经纬度、WiFi BSSID/SSID、蓝牙配对设备与 MAC、卫星通信开关。
  • 通道有结构性问题。 1.2/3.0.1 是明文 HTTP；4.0 上了 HTTPS，但证书校验失败会自动降级回明文，而且 sign 参数是“用公钥加密的密钥”，不是签名——任何人都能伪造。
  • 三版都没有“反诈”能力。 字符串、原生库、网络端点、能力四层全部零命中。但它采的数据集，恰好是反诈画像的理想输入——这是能力问题，不是功能问题。

03四条最硬的问题

全部来自反编译代码，不依赖任何运行时抓包。

缺陷 1 · 认证

sign 不是签名，是加密

RSA/ECB/PKCS1Padding + ENCRYPT_MODE，用随包分发的公钥加密 SHA256(json)。密钥由明文推出，签名由密钥推出——自指闭环，零认证。

缺陷 2 · 加密

GCM 的 IV 从密钥里派生

IV[0..7]=key[0..7]、IV[8..15]=key[24..31]。同一明文→同一密文，构成 GCM 已知的 forbidden attack 前提。

缺陷 3 · 传输

TrustManager 只看有效期

for (X509Certificate c : chain) c.checkValidity(); —— 没有 verify()，没有 pin。自签证书 + SAN=dm.wo.com.cn 即可中间人。

缺陷 4 · 降级

TLS 失败就退回明文

"HTTPS fail by cert invalid, trigger HTTP fallback!" → 重发到 :18080。企业 WiFi、校园网、公共热点都能把整条链路打回明文。

还有一个不是缺陷、但更刺眼的设计： model 与 manuf 明文放在 URL query 上。body 加密得再好，抓包也知道哪款手机在向联通注册。

06查你自己的手机

不需要 root，四条命令就能确认它在不在、跑不跑、发不发。

# 1) 有没有、什么版本
adb shell dumpsys package com.mobiletools.systemhelper | grep versionName

# 2) 权限是否真的被授予
adb shell dumpsys package com.mobiletools.systemhelper | grep granted
adb shell cmd appops get com.mobiletools.systemhelper

# 3) 是否在跑、有没有待触发的闹钟
adb shell ps -A | grep systemhelper
adb shell dumpsys alarm | grep systemhelper

# 4) 是否真的在上报（4.0 注意 :18080 与 :18081 两个端口）
#    用 PCAPdroid / NetGuard 过滤 dm.wo.com.cn 即可

停用与拦截（不依赖 root）

adb shell pm disable-user --user 0 com.mobiletools.systemhelper
adb shell pm revoke com.mobiletools.systemhelper android.permission.READ_PHONE_STATE
# NetGuard / 路由器 hosts —— 黑洞这个域名即覆盖 18080 与 18081
0.0.0.0 dm.wo.com.cn
为什么“封域名”最有效： 3.0.1 起组件用了小米平台密钥签名，系统层面很难停用；但网络层拦截不依赖任何系统授权，对平台签名组件同样生效。
