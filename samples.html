怎么确认你手上这一份
就是报告分析的那一份？

三条 SHA-256、三个签名主体、一段 adb pull。够任何人独立验证，不需要从第三方下载来路不明的二进制。

03从自己的设备取

# 1) 包在不在、什么版本
adb shell dumpsys package com.mobiletools.systemhelper | grep -E "versionName|versionCode"

# 2) 真实路径
adb shell pm path com.mobiletools.systemhelper
#   package:/system/priv-app/SystemHelper/SystemHelper.apk
#   package:/product/priv-app/SystemHelper/SystemHelper.apk
#   package:/data/app/.../base.apk      （升级安装过）

# 3) 拉出来（/system、/product 通常需 root，或从官方固件包解出同一路径的文件）
adb pull /system/priv-app/SystemHelper/SystemHelper.apk

# 4) 校验
sha256sum SystemHelper.apk
没有 root 也可以： 从对应机型的官方固件（super.img / product.img / system.img）里解出该路径下的文件，得到的是同一份二进制。

04哈希一致 / 不一致，分别意味着什么

一致

逐字节相同

报告里的 文件:行号 可以直接对上，所有结论适用。

不一致

可能是另一批次

versionName 相同也可能是 OEM 重打包（如 vivo 机型上的 3.0.1-20251230）。行为可能有差异，值得单独记录并提 Issue。

05为什么不提供"一键安装"

  • 这是 priv-app 组件。 权限来自平台签名（READ_PRIVILEGED_PHONE_STATE、PACKAGE_USAGE_STATS、QUERY_ALL_PACKAGES），普通安装拿不到。
  • 侧载后是空壳。 读不到 IMEI/IMSI，服务起不来，开机广播与保活行为全部不同——装上也复现不了任何东西。
  • 验证结论的正确方式： 静态分析（jadx 打开同一份 APK）+ 自己设备上的抓包，而不是安装。
顺带一句： 未经校验的第三方 APK 包不值得信任——对研究结论是污染源，对设备是风险。拿不到原始文件时，只用哈希去比对别人给出的样本，不要直接装。
