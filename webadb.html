WebUSB · ADB · 可行性

网页能调用 ADB 吗？
能，但只有一种方式，而且限制很多。

直接回答：网页不能运行 adb 这个程序，也不能访问你电脑上的 Android SDK。 但浏览器有一条 WebUSB 通道，可以直连手机的 adbd 守护进程——这就是 ya-webadb 做的事。 下面把边界说清楚，再给你一个不用装任何东西的命令生成器。

能力纯网页说明
执行任意 adb shell 命令部分WebUSB + ADB 协议实现（ya-webadb）可以，但仅限支持 WebUSB 的浏览器
读取 dumpsys / appops / pm list可以这些是普通 shell 权限，接口直接返回文本
截屏、拉取 /sdcard 文件可以同步协议 + 流式传输
拉取 /system/priv-app 里的 APK不行需要 root；非 root 下该路径不可读
pm disable-user 平台签名组件多半失败系统策略会拒绝，返回 SecurityException
安装 priv-app 副本无意义侧载后拿不到平台签名权限，装上也是空壳
在手机上用（iOS / Android 浏览器）不行移动端浏览器不提供 WebUSB
Firefox / Safari不行两者都不实现 WebUSB
一句技术解释： adb 不是一个“接口”，而是一个主机端程序——它用 ADB 协议（USB 上是一组 vendor-specific 端点，TCP 上是 5037 端口的服务协议）跟设备里的 adbd 通信。 网页拿不到本机进程，唯一能做的就是用 WebUSB 自己实现这套协议。能做到，但那等于在浏览器里重写一个 adb 客户端。

03三条可选路径

路径 A · 推荐

本地 adb

最稳。装 Android Platform Tools，一条 USB 线，上面生成的命令直接可用。

支持：Windows / macOS / Linux

路径 B · 纯网页

WebUSB + ya-webadb

桌面 Chrome / Edge，开启「USB 调试」，页面通过 WebUSB 直连 adbd。无插件、无驱动之外的东西。

限制：桌面 Chromium、单设备、需用户手势授权

路径 C · 无电脑

设备端 Termux

手机装 Termux + android-tools，本机自连 127.0.0.1:5555。适合只想在自己手机上查。

需先 adb tcpip 5555（通常要 root 或一次电脑连接）

如果要在自己的页面里接 WebUSB

这条路要引入 @yume-chan/adb 及其 WebUSB 适配层（MIT 许可）。示意代码，未随本站打包，需你自行 npm i 或走 CDN：

import { Adb, AdbDaemonTransport } from "@yume-chan/adb";
import { AdbWebUsbBackend } from "@yume-chan/adb-backend-webusb";

// 1) 必须在用户点击事件里调用（浏览器要求手势）
const device = await navigator.usb.requestDevice({
  filters: [{ classCode: 0xff, subclassCode: 0x42, protocolCode: 0x01 }],
});

// 2) 建立 ADB 连接
const connection = await AdbWebUsbBackend.fromDevice(device);
const adb = new Adb(new AdbDaemonTransport({ connection }));
await adb.connect();                       // 设备端会弹出「允许 USB 调试」

// 3) 跑命令
const result = await adb.subprocess.noneProtocol.spawnWaitText(
  "dumpsys package com.mobiletools.systemhelper | grep versionName"
);
console.log(result);
三个必须知道的坑： ① 同一时刻只能有一个 adb 服务持有设备，先把本机的 adb kill-server 停掉； ② 只在你自己的设备上用，握手时手机上会弹「允许 USB 调试」，别对陌生机器点允许； ③ 页面必须跑在 https:// 或 localhost 下，WebUSB 才可用——GitHub Pages 满足这一点。

04为什么本站没有内置 WebUSB 客户端

  • 体积与维护。 一个完整的 ADB 实现要几百 KB 并按设备能力分叉，塞进一个静态站不划算。
  • 安全边界。 这类页面天然会请求「连接你的手机」。一个研究项目的主页不该顺手拥有这种能力——你需要它时，用上面路径 A/B/C 单独去做。
  • 它解决不了核心问题。 你想知道「它在不在、发不发」，本地 dumpsys 加一次抓包就够了，不需要浏览器。
最省事的自查（一行）： 
adb shell dumpsys package com.mobiletools.systemhelper | grep -E "versionName|versionCode"
有输出 = 装在你机器上；没有输出 = 没有这个包。
